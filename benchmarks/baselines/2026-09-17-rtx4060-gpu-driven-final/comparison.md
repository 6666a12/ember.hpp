# GPU 调度与异步统计对照

已实现可选 GPU 自主调度和有限队列的异步统计。默认同步模式保留；使用 `setGpuDriven(true)` 启用，界面读取 `pollStatistics()`。`aliveCount()` 保持即时准确，必要时会同步等待。

**环境限制：最终复测期间检测到 VALORANT 同时使用 GPU。一次 Windows GPU Engine 采样显示其占用约 50% 的 3D 引擎，GPU 温度达到 87°C；[诊断记录](contention.json) 保留另一时刻的机器读数。同步整轮与 GPU 整轮的后台负载不同，以下大幅耗时差异不能用于宣称实现退化或加速。数据保留用于结果一致性、观测等待位置及复现；附加短程 ABBA 交错核验仍属于共享 GPU 环境。**

同一 RTX 4060 Laptop / NVIDIA 595.71，Release，1280×720 离屏，workload v1 / measurement v2。每种模式包含 11 场景 × 3 容量 × 3 重复 × 3 测量组，共 297 case / 71,280 帧；每 case 预热 120 帧，采样 240 帧。先完整运行 sync，再完整运行 gpu。源码和可执行文件哈希一致，逐帧存活数量完全一致，所有压缩原始数据哈希及聚合结果已重算校验。

measurement v2 每帧将真实计数复制到 GPU 历史缓冲，最后统一读取，采样循环不调用即时计数 API。两种模式承担相同的历史拷贝成本。主指标是从窗口开始到 GPU 完成的平均帧耗时，含目标清空、提交、历史拷贝、查询采集和最终 drain，单位 ms；不是显示帧率。CPU 调用时间包含驱动等待，不能等同于纯 CPU 提交成本。

## 使用边界

GPU 模式消除了下一帧调度对 CPU 计数的依赖，为后续 Vulkan / DirectX / Metal 后端提供相同的异步统计语义。它额外提交调度、拷贝和 fence，排序仍按容量提交步骤；小负载未必获益。因此保留显式开关，不自动按滞后的统计数量切换算法。

计时器开关组与两种模式均串行运行，温度、频率、操作系统调度仍可能影响结果；不要把小幅差异全部归因于调度实现。更低的 update 时间应结合整窗口完成时间评价。

复现命令（输出目录必须不存在）：

```sh
python tools/run_benchmarks.py --scheduling sync --output out/gpu-scheduling-sync
python tools/run_benchmarks.py --scheduling gpu --output out/gpu-scheduling-async
```

## 短程 ABBA 交错核验

同一最终可执行文件按 sync → gpu → gpu → sync 顺序运行；每块 5 场景 × 2 容量，预热 30 帧、测量 120 帧，GPU 时间戳关闭。原始数据、命令和遥测见 [abba/summary.json](abba/summary.json)。每一块逐帧数量一致，哈希及聚合已重算校验。场景/容量顺序固定，后台游戏状态未控制；此表用于核验前面的大幅差异，不构成独占 GPU 性能保证。

| 场景 | 容量 | sync A1 | gpu B1 | gpu B2 | sync A2 |
|---|---:|---:|---:|---:|---:|
| burst | 10000 | 0.505 | 0.151 | 0.154 | 0.179 |
| burst | 1000000 | 1.244 | 1.028 | 1.670 | 0.611 |
| churn | 10000 | 2.648 | 0.508 | 0.757 | 0.242 |
| churn | 1000000 | 6.884 | 5.553 | 7.154 | 2.237 |
| dense | 10000 | 0.211 | 0.681 | 0.554 | 0.244 |
| dense | 1000000 | 8.114 | 4.587 | 7.041 | 2.079 |
| sort | 10000 | 2.099 | 1.318 | 1.822 | 0.475 |
| sort | 1000000 | 14.685 | 18.414 | 53.704 | 4.855 |
| sparse | 10000 | 1.270 | 0.680 | 1.071 | 0.153 |
| sparse | 1000000 | 0.582 | 0.674 | 0.772 | 0.189 |

ABBA 中，仅同步模式自身的百万容量 dense 就从 8.114 ms 变为 2.079 ms，sort 从 14.685 ms 变为 4.855 ms；环境波动显著。因此本次验收确认功能、去除强制计数依赖及结果一致性，不给出最终实现的可靠吞吐加速结论。精确性能比较需要在 GPU 空闲环境重新运行配对基准。
