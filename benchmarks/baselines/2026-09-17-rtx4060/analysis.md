# 首份基线的解读

测试设备为 NVIDIA GeForce RTX 4060 Laptop GPU，驱动 595.71，Windows、GNU 16.1.0 Release。分辨率 1280×720，离屏 RGBA16F，固定粒径和相机。每个组合预热 120 帧，采样 240 帧，重复 3 次。完整条件和统计定义见 [测量说明](../../README.md)，全量表格见 [report.md](report.md)。

## 普通库的百万容量结果

下表来自 `plain` 组，单位为 ms，保留了 GPU 时间戳的包围开销。CPU 帧时间是 update + render 的墙钟时间，包含等待。

| 场景 | 实际存活量 | CPU 帧时间 P50 | P95 | 完成整个窗口后的平均每帧时间 |
|---|---:|---:|---:|---:|
| 基础 dense | 1,000,000 | 1.842 | 2.408 | 1.952 |
| 持续回收 churn | 999,999–1,000,000 | 6.259 | 6.842 | 6.240 |
| 透明排序 sort | 1,000,000 | 58.411 | 60.129 | 58.446 |
| Bloom | 1,000,000 | 3.172 | 3.791 | 3.293 |
| 深度折射 | 1,000,000 | 2.441 | 3.082 | 2.574 |
| 历史分配过百万，仅剩 1% | 10,000 | 0.761 | 1.116 | 0.811 |
| 同容量，只分配过 1% | 10,000 | 0.066 | 0.104 | 0.080 |

这些是合成工作负载，尤其粒径较小，不能直接换算为完整游戏的帧率。单次运行的平均数与跨帧分位数没有必须大小一致的关系。

## 对后续实现最有用的发现

1. **百万粒子的排序首先受 GPU 排序阶段限制。** 分阶段组的 `gpu_sort_ms` P50 为 56.465 ms，远大于积分的 0.501 ms。当前 bitonic 在补齐到 2²⁰ 后需要 210 个比较交换 dispatch，再加一次索引初始化。新后端复用相同算法，不能预期仅靠更换 API 就消除这部分成本。

2. **持续回收与大量出生需要单独优化。** churn 每帧约出生 8,333 个粒子，GPU 出生阶段 P50 为 4.330 ms，积分为 0.512 ms。百万容量 burst 每个填充帧约出生 100,000 个，普通库填充段 CPU 帧时间 P50 为 108.252 ms、P95 为 271.879 ms。整段 burst 的 P50 只有 0.803 ms，因为大部分周期为空闲；只报整体中位数会掩盖洪峰。应进一步分析回收/追加分配的原子竞争，再评估批量分配方案。

3. **高水位扫描的成本可以直接量化。** 两个稀疏场景都只画 10,000 个粒子，普通库 CPU 帧时间中位数相差约 11.5 倍。插桩组的积分 P50 分别为 0.519 / 0.007 ms，构建存活索引为 0.159 / 0.004 ms，绘制均约 0.016 ms。差异集中在扫描阶段，支持后续改为遍历存活索引。

4. **同步读回会把渲染等待记到下一帧 update。** 普通库 sort 的 `cpu_render_ms` P50 只有 0.514 ms，`cpu_update_ms` 却为 57.825 ms；GPU render span 为 57.514 ms。插桩组 readback P50 为 57.831 ms。移除同步读回有利于提交与 GPU 并行，但不能把这些等待时间全部宣称为可消除的仿真成本。

5. **这组 Bloom 场景主要增加额外粒子绘制。** 插桩组离屏粒子绘制约 1.056 ms，Bloom 准备约 0.031 ms，后处理约 0.048 ms。缓存深度附件仍是合理的小改进，但这份数据不支持将它列为当前最大的性能瓶颈。

建议把以上排序、出生、稀疏场景作为 Vulkan / DirectX / Metal 后端的首批对照场景，同时保留 dense 作为基础开销参照。优先比较整个采样窗口的完成时间和相同 GPU 阶段；CPU 调用时间用于观察提交和同步方式的变化。

## 使用边界

全部 297 个 case、71,280 个采样帧均通过完整性校验，原始数据 SHA-256 与汇总匹配。关闭 GPU 计时器后，百万 dense 的 CPU 帧时间 P50 为 1.796 ms（有计时器为 1.842 ms），sort 为 58.468 ms（有计时器为 58.411 ms）；两个稀疏场景分别为 0.724 / 0.057 ms。上述主要瓶颈在对照组中仍然成立，但小负载的测量开销不能忽略。

笔记本采用驱动自动频率，未锁定时钟或供电状态。环境和运行前后遥测保存在 `summary.json`。三个测量组串行执行，应同时查看 `plain_no_timers` 对照表和重复间波动，避免把小差异过度解释为 API 或算法收益。

GL、Vulkan、DirectX 可以在同一块 GPU 上比较；Metal 通常需要另一台机器，其结果应作为独立平台基线。当前数据未覆盖大粒径高 overdraw、宿主场景、呈现延迟、多系统竞争、异步计算或显存峰值。
