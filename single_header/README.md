# ember 单头文件版（single-header edition）

`ember.hpp` 是 ember GPU 粒子库的**单头文件版**：整个库（声明 + 实现 + 可选 GLFW 窗口模块）注入一个文件，**无需编译任何 ember 源码**。

> 🌏 完整文档：中文 [INTEGRATION.md §5](../INTEGRATION.md) · English [INTEGRATION.en.md §5](../INTEGRATION.en.md)

## 用法

```cpp
// 某个 .cpp（整个工程只允许一个 TU 这样写）：
#define EMBER_IMPLEMENTATION      // 展开实现段
#define EMBER_USE_GLFW            // 可选：GLFW 窗口便利模块
#define EMBER_USE_STB             // 可选：PNG 贴图（还需在某个 TU 定义 STB_IMAGE_IMPLEMENTATION）
#include "ember.hpp"

int main() {
    ember::Window win(1280, 720, "demo");
    ember::ParticleSystem sys({100000, 30000});
    sys.setGravity({0.f, -9.81f, 0.f});
    // 主循环：win.pollEvents(); sys.update(dt); sys.render(view, proj, w, h, fov);
}
```

## 依赖（文档化，见 INTEGRATION §2）

| 依赖 | 必需性 | 说明 |
| --- | --- | --- |
| **glad**（`gl:core=4.3`） | ✅ | include 生成的 `glad.h` + 编译 `glad.c`；`ember::gl::init(loader)` 注入 |
| **glm**（≥ 0.9.9） | ✅ | 头文件库，加 include 路径 |
| GLFW 3.4 | 仅 `EMBER_USE_GLFW` | 窗口模块 |
| stb_image | 仅 `EMBER_USE_STB` | PNG 贴图；未定义则回退内置渐变 |

## 与模块化版的关系

单头文件继续包含完整 GL 后端；新增的纯公共层构建请使用模块化 `ember::core`。后端边界和选择见 [后端说明](../docs/backends.md)。

- 同一份代码、同一 shader 契约（binding 0-13、批量出生与分块排序兼容协议见 INTEGRATION §8）
- `ember.hpp` 由 [`tools/amalgamate.py`](../tools/amalgamate.py) 从 `include/ember/` + `src/` 生成：
  ```bash
  python tools/amalgamate.py          # 重新生成
  python tools/amalgamate.py --verify # 检查是否有漂移
  ```
- 等价性由 `tests/single_header_test.cpp` 保证：只用单头文件编译整库（不链 ember），跑全部断言 + 像素检查

# ember single-header edition

`ember.hpp` is the **single-header edition** of the ember GPU particle library: the whole library (declarations + implementation + optional GLFW window module) in one file — **no ember sources to compile**.

## Usage

```cpp
// in one .cpp (only ONE translation unit in the whole project):
#define EMBER_IMPLEMENTATION      // expands the implementation into this TU
#define EMBER_USE_GLFW            // optional: GLFW window convenience module
#define EMBER_USE_STB             // optional: PNG sprites (also define STB_IMAGE_IMPLEMENTATION somewhere)
#include "ember.hpp"

int main() {
    ember::Window win(1280, 720, "demo");
    ember::ParticleSystem sys({100000, 30000});
    sys.setGravity({0.f, -9.81f, 0.f});
    // main loop: win.pollEvents(); sys.update(dt); sys.render(view, proj, w, h, fov);
}
```

GPU scheduling is available through `sys.setGpuDriven(true)`. Use `pollStatistics()` for asynchronous UI counts; `aliveCount()` remains exact and may wait. The scheduler is embedded, so this mode also works without shader files. See [the integration guide](../INTEGRATION.en.md#gpu-scheduling-and-asynchronous-statistics-opt-in).

## Dependencies (documented, see INTEGRATION §2)

| Dependency | Required | Notes |
| --- | --- | --- |
| **glad** (`gl:core=4.3`) | ✅ | include its generated `glad.h` + compile `glad.c`; `ember::gl::init(loader)` |
| **glm** (≥ 0.9.9) | ✅ | header-only, add the include path |
| GLFW 3.4 | only with `EMBER_USE_GLFW` | window module |
| stb_image | only with `EMBER_USE_STB` | PNG sprites; falls back to the built-in gradient otherwise |

## Relationship to the modular build

The generated header still includes the complete OpenGL backend. For a graphics-independent build, use the modular `ember::core` target and inject a `ParticleBackend`.

- Same code, same shader contract (bindings 0-13, INTEGRATION §8)
- `ember.hpp` is generated by [`tools/amalgamate.py`](../tools/amalgamate.py) from `include/ember/` + `src/`:
  ```bash
  python tools/amalgamate.py          # regenerate
  python tools/amalgamate.py --verify # check for drift
  ```
- Equivalence is guaranteed by `tests/single_header_test.cpp`: it compiles the whole library from the single header only (no ember link) and runs all assertions plus a pixel check.
