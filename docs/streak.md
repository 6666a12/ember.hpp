# 拖尾拉伸专项检查

`setStreak(k)` / `[system] streak` 是每粒子的瞬时 billboard 拉伸。它没有保存历史位置，无法画出转弯轨迹；额外长度对称分布在粒子前后，没有独立的尾部寿命或沿尾部渐隐。鼠标跟随的 `spark trail` 则是发射器沿途产生独立粒子，也不是一条连续 ribbon。

## 本次确认并修复的问题

1. **透视运动投影不完整**：原来只取视图速度 `v.xy`。例如粒子位置 `(1,0,-3)`、速度 `(0,0,6)`，其屏幕中心明显横移，却完全不拉长；反过来沿相机视线 `(-1,0,3)` 运动，中心 UV 不变，却生成了横向拖尾。现在透视情况下使用 `v.xy - p.xy * v.z / p.z`，即屏幕中心运动在当前深度平面上的等效速度；正交投影仍使用 `v.xy`。相机变换先作用于位置和速度。
2. **极低速朝向突变**：哪怕只剩极小的纵向速度，也会把不对称贴图旋转 90°；到速度为零时又回到横向。现在额外伸长从 0 到原尺寸的 10% 时，按最短角路径从普通 billboard 朝向过渡到运动朝向，停止时保持普通自旋。
3. **折射法线与几何脱节**：streak 已经接管几何朝向，自旋仍单独转动折射法线。现在 quad、穹顶方向与面片法线统一使用最终朝向。

上述问题通过真实 GL 像素回归复现；测试位于 `tests/streak.hpp`，在模块化和单头文件测试中共同执行。6 组检查覆盖横向/纵向长度、居中范围、离轴纵深运动、沿视线运动、正交投影、低速/停止、自旋与折射的组合，以及相机旋转。常规拉伸同时验证同步和 GPU 调度模式。

## 参数与边界

最终长轴长度仍为 `size × sizeScale × (1 + k × projectedSpeed)`，短轴宽度不变。`k <= 0` 关闭拉伸；`k` 不是以秒计的尾迹保留时间。改变粒子尺寸也会改变拖尾长度。

当前计算只包含粒子自身速度，没有相机速度历史，因此不模拟相机运动的快门拖影。方向过渡也没有时间滤波；剧烈转弯或反向仍立即响应当前速度。拉伸体处于粒子中心的视图深度平面，排序、软粒子与深度测试使用该平面，没有沿尾迹的三维深度变化。

若要火花“头部固定、尾部向后”，需要单独的后向锚点与渐隐规则；若要保留连续弯曲轨迹，需要记录位置历史并生成 ribbon/分段几何。这两种行为会改变现有 `streak` 的含义，应作为明确的模式或独立功能接入。
